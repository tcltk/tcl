* **v18d** (27 novembre) : tuple à gauche de `is`. Demande de l'utilisateur : `is` teste la valeur à droite d'une affectation par tuple ; si c'est ambigu (on écrit plutôt `Z is Complex = (a,b)`), une erreur. Fait : `((a,b) = $Z) is T` teste la valeur affectée (`IsLeftTupleAssign`, commande `::tcl::unsupported::isvalue valeur type` : type de la valeur inclus dans T, variante et charge pour S/v, ou valeur nue valide) ; `(a,b) = Z is T` (le tuple recevrait le booléen) : erreur à l'exécution, `ambiguous: (a,b) = Z is T assigns the result of "is" to the tuple; write ((a,b) = $Z) is T to test the value, or Z is T = (a,b) to declare Z`. t141 complété ; `noyau/is-tuple.patch` (nouveau, après `is-affectation.patch`). Première livraison v18d : `is-affectation.patch` avait été refait au lieu d'ajouter un patch, et `maj.sh` sur un arbre en v18c n'y reconnaissait plus rien (« CONFLIT types-binaires-set-annotation-locale.patch, déjà appliqués : 0 ») ; corrigé, `is-affectation.patch` est revenu à sa forme v18c. **Règle : un patch livré ne change plus ; une correction est un nouveau patch en fin de `ORDRE.txt`.** Vérifié par `maj.sh` sur des copies d'arbre en v18b et v18c (dry-run, puis application : `tclCompExpr.c` identique) ; tests_tclsh (121) dans tous les modes (off : t120 comme avant) ; valgrind propre.
* **v18c** (27 novembre) : `(r = valeur) is T`. Point de départ : un correspondant écrit `if {[set {result}r [openfile $fn]] is result/ok}` (une valeur à gauche de `is`) ; discussion : faire de `$x`/`[cmd]` une valeur devant `is` casserait l'accord avec la TIP 759 (à gauche de `=` et des autres opérateurs, un nom) ; retenu : une affectation entre parenthèses désigne sa variable, comme une lvalue de C++. `[type get $r] is …` ne marche pas (la chaîne est lue comme un nom : 0). * **v18b** (27 novembre) : la variante, un type. Valeurs : annotées S/v (`TypeRefObj` : variante v) ; `TypeCastEx` : S/v → S (même valeur, variante v), S ou S/w → S/v (même variante : telle quelle ; autre : erreur implicite, règle `type convert` si écrit) ; `ValidateG` : S/v n'admet que v, et une valeur déjà annotée d'une somme de même racine donne sa variante (élément, argument) ; la charge d'une somme peut être une valeur annotée d'une autre somme (gardée pour la validation de la variante). Sommes imbriquées : `{/some}$t` (`BuildSum`, `TclTypedConformHint`, `TclAnnotSettle`), étiquettes en chaîne `{/some/celsius}5` (`LabelRestType`, `SettleLabelChain`, `TclAnnotLabelIndex` lit le premier membre), `TclNewAnnotated` d'un S/v/w annote la charge, `AsRootValue` ; `TclTypeComplete` normalise la charge d'une valeur annotée ; `type get` / `type canonic` écrivent la chaîne (`TclAppendPayloadChain`), `type parse` la relit ; `is` (`IsOpObjCmd`) vérifie variante et charge ; inclusion (`IncludesD`, `TypeIncludes`) par la restriction ; lappend et listes : la variante d'un élément est relue (`TclTypeSumRoot`). Messages : `value "5.0" is temp/fahrenheit, not temp/celsius`, `value "**" is not a binop/"+"`, noms des littéraux dans les règles. Sorties revues : littéraux (`M/auto`, `onoff/on`, `opt(rec)/none`, `pi/"3.14159"`), casts vers S/v (`{S110/d}2.0`), t94 (la somme imbriquée marche). t140 (type S/v, listes, inclusion, `is`, littéraux, imbriquées, chaînes) ; fuzz `fzvar.tcl` et `fzvar_proc.tcl` (sommes à deux et trois niveaux, littéraux, chaînes : construction, `type get`, canonic/parse, cast, `is`, listes, arguments, retours, variables du type entier ; global et compilé ; on, off, sans cases) : 0 écart ; fuzzers précédents identiques ; tests_tclsh (120) en on, check, sans blocs, sans tuple, `TCL_TYPES_COMPACT=0` (off : t120 comme avant).

* **v17z** (27 novembre) : la variante d'une somme devient une métadonnée (note `doc/CONCEPTION-sommes-num.md`, discutée et validée). `TclSumTagged` ne vaut plus (la valeur est la charge seule) ; `TclSumStrict` (une somme `,`, pas une union ni une somme binaire) et `TclSumLabeled` (somme ou union) disent les politiques. ## 4. Décisions de conception arrêtées

**Valeurs annotées**
* Valeur annotée A = (V contenu, T référence de type). Une annotation locale (`{-x}`, `{x?}`,
  `{x!}`) ne vit qu'entre l'appelant et la commande ; posée sur une valeur, elle ne garde que le
  contenu.
* Résolution d'une annotation : dans le contexte d'abord (variantes d'une somme, champs d'un
  produit), puis les types globaux ; sinon c'est une note. Une annotation ne vient jamais du
  contenu d'une chaîne.
* **Contrat par le nom (v14)** : seule une déclaration (`set {T}v`, `x is T = v`, `lappend {T}M`…)
  pose un contrat ; une variable non déclarée reçoit une valeur typée sans contrat. Sans contrat,
  une modification est un calcul ordinaire ; sous contrat, le résultat est vérifié au rangement
  et un refus laisse la variable intacte.
* **Scalaires et conteneurs (v16t)** : `list`, `dict` et les produits se déplient dans la vue
  liste (un produit en ses champs, chacun typé) ; un scalaire typé (chaîne, nombre, littéral), un
  lien est UN élément ; une somme prend la nature de sa variante active. (v15 à v16s : « règle
  B », un produit était UN élément.)

**Sommes**
* Déduction de la variante : la plus stricte. Plusieurs variantes également strictes = erreur
  `TCL TYPE AMBIGUOUS T v`, le message propose `{variante}valeur` et `set {S}v(variante) valeur`.
  **Décision implicite gardée** : à égalité, la variante courante de la variable départage.
* Conversions entre variantes d'une même somme (v15n), faites sur une copie.

**Construction d'un produit (v13)**
* 1 argument de même type = copie ; `{T.champ}valeur` ; *n* valeurs pour *n* champs =
  positionnel ; 0 argument = défauts ; sinon `wrong # args … write {field}value or set {T}var(field,...)`.
* Étiquettes : tout ou rien ; une étiquette portée par une variable compte.

**Chemins** (`tclTypePath.c`)
* Opérateurs `,` `.` `:` `( )`, `*` unaire et `*` seul (toutes les parties) ; construction
  `set {rect}R((A,B).(x,y)) …`.
* Le chemin ne substitue rien : dans `{…}` et `${…}`, `$` et `[` sont des erreurs. Les valeurs
  substituées par Tcl dans `$nom(...)` sont atomiques (`pathindex`, `INST_INDEX_CONCAT`).
* Côté noyau : `TCL_TOKEN_INDEX` par `Tcl_ParseVarIndex`, repli exact sur la règle Tcl 9 quand
  l'index n'est pas bien formé (`info complete` inchangé).

**Forme compacte (v15p, v15q)**
* Seulement les formes canoniques ; `int(s,n)`, `int(u,n)`, `double` ; alignement naturel
  (mesuré par `tcl::unsupported::abi`) ; commandes sous `tcl::unsupported::compact`.
* `type def {-compact}T` : l'annotation est sur le nom du type ; la valeur est normalisée à la
  construction ; les conversions se font sur une copie. Interrogation `type is {compact?}T`
  (ou `$v`). Export : `type {c!}export T` (en-tête C avec `_Static_assert`), `{llvm!}` prévu.
* API C pour les extensions : `tclAnnotatedApi.h`, fonctions `static inline` en attendant des
  entrées de stub (`Tcl_AnnotatedGetType`, `Tcl_AnnotatedCreate`, `Tcl_AnnotatedGetParts`,
  `Tcl_AnnotatedGetCells`). Exemple : `exemples/geometrie/geo.c`.

**Binaire**
* `type binary` / `chan binary` ; liens `*(origine,repr).T`, `-linkdepth`, référentiels nommés,
  `-dedupe` ; codecs C pour les cas mesurés, repli sur le codec Tcl (`set ::tcl_typebinaryc 0`).

## 5. Prochaine étape

**Performances.** Après la v16c, l'étape annotée de l'exemple `geometrie` est à 1,1 à 2,8 fois
le Tcl nu, les voies C de 3 à 150 fois plus rapides que lui. `X is T = v` est une instruction
(`declareLocal`), `$a(x)` opérande d'un opérateur arithmétique est lu comme nombre (`loadFieldNum`,
≈ 60 ns). Le codec C couvre depuis la v16d les tailles calculées, les préfixes, `at(...)` et les
liens (restent : référentiels nommés, `-linkdepth` fini, `-dedupe`, lien nul à défaut). Restent aussi : de vraies entrées de stub (les fonctions de `tclAnnotatedApi.h`), les appels de
procédure (avec les signatures), la vue fabriquée par chaque `lindex` d'une liste en cases.
`set {T}x a b…` est passé en v16g de 1,3 à 0,6 µs pour un point (`X is point = (…)` : 0,2 µs) ; le reste
est l'appel de `::tcl::annotraw` (objet annoté créé puis libéré à chaque tour, texte du type relu) :
le compiler sans cet appel serait l'étape suivante.
Bancs : `exemples/geometrie/bench.tcl` et `bench_parties.tcl` ; profil avec callgrind.

Les autres points ouverts sont dans le planning et au § 17 de `doc/ANNOTATIONS.fr.md`, entre
autres :
* valeur « inexistante » en général (`opt(T)` ne couvre que les liens binaires) ;
* annotation de commentaire `{#}`, du premier mot, de déclaration dans `proc` ;
* notes par élément d'une liste typée ;
* forme compacte : cases à pointeurs (listes de taille variable, chaînes), `lindex` sans vue neuve, `lappend` en temps
  constant, `{-compact}` pour une famille ;
* `type {c!}export` pour les types récursifs, cible `{llvm!}`, sens inverse (en-tête C →
  `type def`) ;
* codecs C pour sommes, liens et tailles calculées ;
* exemples `arbre_var.tcl` et `defauts_calcules.tcl` à corriger ; banc C sur maquette.

**Ballet céleste (à garder en tête, 21 novembre 2026).** Faire de la démonstration
Terre-Lune (`earthmoon.tcl`, matrices 4×4, opérateurs utilisateur `\name`) une application
à part entière, et un point d'entrée de Tcl dans l'enseignement, à plusieurs niveaux. Il
faut pour cela un Tcl qui porte **à la fois la TIP 759 et la TIP 764**. Écart à combler : la
TIP 759 (branche `tip-759h-tcl91-user-op`) est sur Tcl **9.1.1**, l'arbre de typeparse sur
Tcl **9.0.5** ; les deux touchent l'analyseur (`tclParse.c`, `tclCompExpr.c`, `tclCompile.c`),
on attend des conflits. Pistes laissées avec la démo : quaternions et caméra en slerp,
opérateurs mixtes vecteur/scalaire, opérateurs `cproc` typés par la TIP 764.

## 22/11 — crible d'Ératosthène : performances (corrigé en v17l, 23/11 ; voir plus haut)

Mesures (`/tmp/crible/b.tcl`, tclsh typeparse v17k), N = 100 000 :

| variante | temps |
|---|---|
| liste ordinaire + `lset` | 19 ms |
| `bitarray(1000000)` + `set b($j) 1` | 1 482 ms (×75) |
| `list.bitarray(64)` + `set L(w.b) 1` | 1 034 ms (×50) |
| `{-compact} list.int(u,8)` + `lset` | quadratique : 932 ms à N = 2 000, 13 s à N = 8 000 |

* L'écriture d'un bit d'un grand `bitarray` coûte O(n) (le grand entier est
  recopié à chaque écriture, même non partagé).
* `lset` sur une liste compacte semble repasser par la forme ordinaire à chaque
  écriture : O(n) par écriture, O(n²) en tout. Une écriture en place (valeur non
  partagée) devrait être O(1).
* `bitarray` n'est pas admis dans une liste compacte, et sa largeur est bornée à
  1 000 000.
* `set {list.T}v` prend les éléments en arguments (`{*}[lrepeat …]`), et
  l'annotation d'un `set` n'est lue que littérale (`set "{bitarray($W)}b"` ne
  type pas).
